  This file is a Folio Pages document: a word processor and its document
  in one HTML file (format folio/doc, version 1, app {{VERSION}}).
  Full guide: https://emyotyyy.github.io/folio-pages/agents.md
  JSON Schema: https://emyotyyy.github.io/folio-pages/schema/folio-1.json

  THE MECHANICS
  · The document is the ONE script block of type "application/folio+json"
    with the id folio-doc, just below this comment. Edit THAT block in
    place. Never regenerate or retype the whole file.
  · The script blocks of type "folio/deflate-b122" further down are the
    compressed application. They hold no user content: leave them alone,
    byte for byte. They contain non-ASCII and control characters: read and
    write the file as UTF-8, and change only the bytes of the folio-doc block.
  · Write every "<" inside the JSON as <, so the JSON can never close
    its own script tag.
  · An empty block means "no document yet" (the app shows a demo). To make
    a document, put your JSON into the empty block.
  · Leave "id" out of a new document: the app creates one. Never change
    the "id" of an existing document.
  · A block holding { "format": "folio/enc", … } is a document protected
    by a password: it cannot be read without it. Do not change it; tell
    the person to open it, or to send an unprotected copy.
  · In a running file: window.folio = { doc, serialize(), loadDoc(json),
    schema(), i18n }. In the app: the AI tab, Copy JSON / Replace from JSON.

  MINIMAL DOCUMENT (fields at their default value may be left out)
  {
    "format": "folio/doc",
    "version": 1,
    "meta": { "title": "Weekly report", "lang": "en" },
    "blocks": [
      { "type": "heading", "text": "Weekly report" },
      { "text": "A paragraph of plain text." },
      { "md": "A paragraph with **bold**, *italic* and a [link](https://example.org)." },
      { "type": "heading", "level": 2, "text": "Tasks" },
      { "type": "list", "items": ["First", { "text": "A sub-point", "level": 1 }, "Second"] },
      { "type": "list", "style": "number", "items": ["Step one", "Step two"] },
      { "type": "table", "rows": [["Item", "Cost"], ["Paper", "12 €"]] },
      { "type": "quote", "text": "A quotation." },
      { "type": "code", "language": "python", "text": "print('hello')" },
      { "type": "divider" }
    ]
  }

  BLOCKS
  · paragraph: "type" may be left out; a plain string is a paragraph too.
  · heading: "level" 1 to 6 (default 1).
  · list: "style" "bullet" (default), "number" or "check", "start"
    (default 1), "items": strings, or objects with a "level" from 0 to 8
    for nesting ("checked": true ticks a check list item).
  · quote: one paragraph (text/md) or "blocks".
  · code: "language", "text" with \n between lines.
  · table: "header" (true by default: the first row is the header),
    "rows": arrays of cells; a cell is a string or
    { "text"|"md", "colspan", "rowspan" }.
  · equation: a centred formula in LaTeX, { "type": "equation", "tex":
    "\\int_0^1 x^2\\,dx = \\frac{1}{3}" }; "numbered": true numbers it (1),
    (2)… Put \\label{name} in it and write \\eqref{name} elsewhere.
  · chart: "kind" "bar", "line" or "pie", "title", "labels" (the
    categories) and "series": [{ "name", "values": one number per label }];
    or "rows" like a table (first row: series names, first column: labels).
  · diagram: "kind" list, process, cycle, hierarchy, pyramid or radial,
    "title", "items": strings, or { "text", "level" } for sub-items (an
    organisation chart uses levels 0, 1, 2…).
  · pictures: pictures with captions, arranged; "layout" grid, strip,
    featured, process, list or mosaic, "title", "items": [{ "src":
    "asset:<id>", "caption", "text" }] (leave "src" out for an empty frame
    the reader fills in later; at most 12).
  · shapes and text boxes go INSIDE a paragraph's "content", first:
    { "type": "shape", "shape": "roundRect" (or ellipse, rightArrow,
    star5, wedgeRectCallout, flowChartDecision, line…), "x", "y" (points:
    from the left margin and from the top of that paragraph), "width",
    "height", "wrap": "front", "behind", "square", "topBottom" or "inline",
    "fill"/"line" (theme colour, #rrggbb or "none"), "text" or "md" }.
    A text box: "shape": "textBox" (the text goes around it by default).
    A group: "shape": "group", "children": [shapes placed from its corner].
    A picture placed freely: "shape": "picture", "src": "asset:<id>",
    "alt" (an "image" block is for a picture on its own line).
    Optional: "rotate", "flip", "lineWidth", "dash" (dash, dot…), "head" /
    "tail" ("triangle" makes an arrow), "transparency", "shadow", "z"
    (stacking), "valign" of the text, "hidden", "blocks" for rich text.
  · callout: "kind" note, tip, important, warning or caution, "title",
    then text/md or "blocks".
  · divider: a horizontal line.   · pagebreak: start a new page.
  · image: "src" is "asset:<id>" with the picture in the top-level
    "assets": { "<id>": "data:image/png;base64,…" } (a data: URI in "src"
    works too). Add "alt" (what it shows), "caption", "width" in points
    (the text is about 470 pt wide), "align", "wrap": "none" (own line),
    "left" or "right" (text flows around it), "tight" (text follows the
    outline of a transparent PNG; side from "align"), "behind" or "front"
    (over the text, taking no room). Optional: "crop" { "top", "right",
    "bottom", "left" } in percent, "rotate" (90, 180, 270), "flip" ("h",
    "v"), "border" (a colour), "adjust" { "brightness", "contrast" (-100 to
    100), "saturation", "recolor" ("grayscale", "sepia"…), "transparency",
    "shadow", "glow", "softEdges", "reflection" }.
  · glossary / abbreviations: the terms of the top-level "terms": [{
    "term": "WHO", "definition": "World Health Organization", "kind":
    "abbreviation" }] ("kind" "glossary" by default) used in the text.
  · authorities (legal): lists the xe runs that have an "authority".
  TEXT of a paragraph, heading, list item or cell, one of:
  · "text": plain text, used as is; \n is a line break;
  · "md": Markdown: **bold**, *italic*, ++underline++, ~~strike~~,
    `code`, ^superscript^, ~subscript~, [link](https://…), fields
    {{page}}, {{pages}}, {{title}}, {{author}}, {{date:DD/MM/YYYY}},
    footnotes: Text.^[The note, numbered automatically.], and formulas
    in LaTeX: $E = mc^2$ in the line (no space just inside the $ signs),
    $$…$$ alone in its paragraph for a centred equation.
  · "content": runs, e.g. ["plain ", { "text": "bold", "bold": true }].
    Run marks: "bold", "italic", "underline" (with "underlineStyle":
    double, thick, dotted, dashed, wavy, and "underlineColor"), "strike",
    "code", "sup", "sub", "link" (https://…, mailto:…, #anchor), "color"
    ("#rrggbb" or "accent1"…"accent6"), "highlight" ("yellow"…), "font",
    "size" (points), "caps", "smallcaps", "letterSpacing", "lang"; effects
    "outline", "shadow" (true), "glow", "textBorder", "textShading"
    (colours).
    A field is a run: { "type": "field", "name": "page" } (title, author,
    date with "format": "DD/MM/YYYY", time, pages, filename…).
    A form field (fill-in forms): { "type": "formfield", "kind": "text",
    "name": "Name", "placeholder": "…" }; kinds dropdown ("options"), date,
    checkbox ("checked"); "formsOnly": true at the top level locks the rest.
    An attached file: { "type": "attachment", "src": "asset:<id>", "name":
    "budget.xlsx" }, its data a "data:application/octet-stream;base64,…"
    asset.
    A note is a run too: { "type": "note", "text": "…" } (bottom of the
    page), with "kind": "end" for an endnote, or "md" / "blocks".
    A formula is a run too: { "type": "math", "tex": "x^2" }.
    Comments (only when asked to review): a run { "text": "…",
    "comments": ["c1"] } and, at the top level, "comments": [{ "id": "c1",
    "author": "AI", "text": "Check this figure." }] (a thread may have
    "replies": [{ "author", "text" }] and "resolved": true).
    Suggested edits (only when asked): { "text": "old", "deleted":
    { "author": "AI" } } then { "text": "new", "inserted": { "author": "AI" } };
    a formatting change: { "text": "key", "bold": true, "formatChange":
    { "author": "AI", "before": {} } } (before: only the marks that were
    set). "trackChanges": true at the top level tracks later edits.
    Mail merge (only for form letters, labels…): a run { "type":
    "mergefield", "name": "First name" } (in md: {{merge:First name}}),
    and at the top level "mailMerge": { "type": "letters", "source": {
    "name": "list", "fields": ["First name", "Email"], "records":
    [["Ada", "ada@example.org"]] } }. See agents.md.
  OPTIONS, all optional:
  · paragraphs and headings: "align" (left, center, right, justify),
    "spacing" { "before", "after" } and "indent" { "left", "first" } in
    points, "line" (1.5…), "keepNext", "keepLines", "pageBreakBefore"
    (true), "shading" and "border" (colours), "dropCap" (2 to 10 lines),
    "dir": "rtl" (Arabic, Hebrew); paragraphs: "style": "title",
    "subtitle", "caption", or a style you define in the top-level "styles"
    ({ "name", "basedOn", "next", marks and paragraph options }).
  · lists: "numbering" (decimal, alpha, roman, outline), "bullet" ("✓"),
    "continue": true (carry on the previous numbered list).
  · tables: "style" (grid, lines, zebra, boxed, minimal), "widths" in
    points, "repeatHeader": true (header row on every page), "firstColumn",
    "border" (a colour), "rowHeight" (points); cells: "bg", "valign",
    "textDir": "tbrl" (vertical).
  · charts: "legend", "horizontal" (bars).
  · "theme": { "name": "classic" } (folio, classic, modern, slate, ink,
    system); its colours accent1…accent6 can be used by name everywhere.
  PAGES (all optional): "page": { "size": "A4" or "Letter"…, "orientation":
    "landscape", "margins": { "top", "right", "bottom", "left" } in mm };
    "headers"/"footers": { "default": [ blocks ] } on every page, e.g.
    { "md": "Page {{page}} of {{pages}}", "align": "center" }.
  · { "type": "columns", "count": 2, "blocks": [ … ] }: text in columns
    ("gap" in points, "rule": true; a { "type": "columnbreak" } inside).
  · { "type": "section", "numberStart": 1 }: a section break; what follows
    starts a new page ("start": "odd" or "even"), may restart numbering
    ("numberFormat": "roman"…), have its own "headers" ("firstPage": true
    for a different first page), and its own "page": { "orientation":
    "landscape" } (a wide table).
  · "watermark": { "text": "DRAFT" } (or "image": "asset:<id>") behind
    every page; "lineNumbers": true; "hyphenate": true.
  · { "type": "toc" }: a table of contents of the headings, always up to
    date ("levels": 3, "title": "Contents").
  REFERENCES (all optional, all kept up to date by the app):
  · Citations: top-level "sources": [{ "id": "Darwin1859", "type": "book",
    "authors": ["Darwin, Charles"], "title": "On the Origin of Species",
    "publisher": "John Murray", "year": "1859" }] (types: book, article,
    chapter, website, report, thesis…; "container" is the journal or site;
    also "editors", "place", "volume", "issue", "pages", "edition", "url",
    "doi", "isbn", "accessed"),
    a run { "type": "cite", "id": "Darwin1859", "locator": "p. 12" } where
    a source is used, and a { "type": "bibliography", "title": "References" }
    block. "citationStyle": "apa" (default), "mla", "chicago", "harvard",
    "ieee" or "iso690" formats them all.
  · Captions: a paragraph { "style": "caption", "content": ["Figure ",
    { "type": "seq", "label": "figure" }, ": A harbour"] } (labels figure,
    table, equation); { "type": "figures" } lists them with their pages.
  · Cross-references: { "type": "bookmark", "name": "harbour" } in the target
    paragraph, and { "type": "xref", "target": "harbour", "show": "label" }
    (text, label, number, page, above) where you refer to it.
  · Index: a run { "type": "xe", "term": "photosynthesis" } beside the word
    (invisible; "sub" a subentry, "see" a "See …" reference), and an
    { "type": "index" } block at the end. Legal citations: "authority":
    "cases" (statutes…) and "short" on the xe, and an "authorities" block.
  SEVERAL DOCUMENTS IN ONE FILE (only when asked: a report and its annexes,
  chapters, a letter and its attachments…): give the first document a
  "key" and put the others, each a complete document with its own "key",
  "meta", "page", "blocks"…, in its "documents": [ … ]. They show as tabs.
  Link to another one with "link": "#annex:sales" (its bookmark or heading)
  or "#annex:" (its start); a cross-reference adds "doc": { "type": "xref",
  "doc": "annex", "target": "sales", "show": "label" }.
  Many documents: arrange them in folders with "tree" in the first
  document, e.g. "tree": ["intro", { "folder": "Chapters", "items":
  ["ch1", "ch2"] }, "annex"] (keys and folders, folders inside folders).
  · "notes": { "foot": { "format": "symbols" }, "end": { "format":
    "decimal" } } changes how notes are numbered (optional).
  "meta" also takes "author", "subject", "organization", "keywords".
  OTHER TOP-LEVEL FIELDS, only when asked: "goal": { "words": 1500 } (a
  writing goal), "fonts" (embedded fonts: { "family", "src": "asset:<id>" }),
  "template": true (each opening starts a new document from it),
  "readOnly": true (opens in reading view). Hand drawing ("ink" on a
  paragraph) is best left to the app.
  Or give the whole document as Markdown instead of "blocks":
  { "format": "folio/doc", "version": 1, "markdown": "# Title\n\nText" }.

  MAKE A GOOD DOCUMENT, NOT JUST A VALID ONE
  · Write in the language of the request, and set meta.lang ("fr", "en"…).
  · Set meta.title: it names the browser tab and the saved file.
  · Structure with real headings: one level-1 heading for the title, then
    levels 2 and 3. Never fake a heading with bold text or capitals.
  · Data, comparisons, schedules, prices: a table with a header row, not a
    list of numbers or tab-separated text. Trends and shares: add a chart.
  · Steps in order: a numbered list. Points in no order: a bulleted list.
    Nest only as deep as the ideas really go.
  · Short, complete paragraphs. No filler and no placeholders such as
    "Lorem ipsum" or "[insert here]".
  · Maths, physics, chemistry: real LaTeX formulas, never pictures or
    plain text: $…$ in a sentence, an "equation" block for anything that
    deserves its own line, "numbered": true when the text refers to it.
    Matrices, cases, aligned, \\frac, \\sum, \\int, \\ce{H2O} for chemistry
    and \\pu{9.81 m/s^2} for units all work. Shared macros go in the
    top-level "math": { "macros": "\\newcommand{\\R}{\\mathbb{R}}" }.
    A price is not a formula: "5 $" stays text.
  · Sources: real citations, never invented ones. Several sources: list
    them in "sources", cite them with "cite" runs, end with a "bibliography"
    block. One passing source: a footnote (md: …^[Author, Title, 2024]).
    Long document (several headings): a { "type": "toc" } after the title.
  · Look: choose a theme, and use styles (title, subtitle, headings) and
    theme colours rather than colouring or resizing runs one by one.
  · Pictures: only real ones you were given or can embed as data; always
    with "alt" text, and a caption when it helps.

  BEFORE YOU FINISH, CHECK
  [ ] Only the #folio-doc block changed; the rest of the file is untouched.
  [ ] The JSON parses: no trailing commas, no comments; every "<" is <.
  [ ] "format": "folio/doc" and "version": 1 are present; "id" is absent
      (new document) or unchanged (existing document).
  [ ] meta.title and meta.lang are set.
  [ ] Headings are real headings, data is in tables, steps are numbered.
  [ ] Every image has "alt" text and its data in "assets" (or in "src").
  [ ] Formulas are LaTeX in $…$ / "equation" blocks, with no space just
      inside the $ signs, and every \\eqref names an existing \\label.
  [ ] Every "cite" id is in "sources"; every "xref" target is a bookmark
      (in the document named by its "doc", if any).
  [ ] Several documents: each has its own "key"; every key in "tree" and
      in "#key:" links names one of them.
  [ ] Nothing is invented that the request or the sources do not support.
